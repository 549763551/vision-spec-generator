# vision-spec-generator · 机器视觉成像方案自动生成器

输入一张样品图和四行检测需求，输出一套可落地的成像方案：相机、镜头、光源、控制器，
并附上每一步的计算式、出处和自检结论。

一句话主张：**让选型从"填表算数"变成"看图说话"——先判断这张图能不能检出，再倒推还缺什么硬件。**

版本：v0.5.0

---

## 1. 它解决什么问题

小批量多品种的产线，每换一个产品就要重新选一次相机、镜头、光源。
这件事目前靠人：翻厂商样本册、凭经验试、拿实物打光试错。
一个熟练工程师配一套方案通常要 30~45 分钟，而且结论留在个人脑子里，换人就重来。

本项目把这段过程变成可复算的程序：
输入客观条件（视野、精度、是否运动、样品图），输出带计算过程的方案书。

**不做的事**：不做光学仿真，不控制物理光源，不替代实拍验证。

---

## 2. 与已有方案的差异

| 现有做法 | 本项目 |
|---|---|
| 选型软件只填参数表，不看图 | 先诊断样品图（灰度差、过曝、清晰度），用图像证据修正选型 |
| 算完直接输出，错在装配时才发现 | 算完**代回公式复算**，检查景深、工作距离、曝光、靶面、通道冲突 |
| 结论不可追溯 | 每一步计算式都标注推导依据，可逐条核对 |
| 落不到具体软件 | 同一份流程可导出四种平台的节点命名，参数值不变只换叫法 |
| 依赖第三方库，环境装不上就跑不了 | 零第三方依赖：计算用标准库，图像解码复用系统 ffmpeg |

最小创新点：**自检复算层**。市面上的视觉软件只做算法不做选型，选型工具只填表不看图，
本项目的差异在"生成方案 → 代回公式 → 发现冲突 → **反解修法**"这个闭环：
冲突项不止报错，还把"该调哪个参数、调到多少"算出来（光圈收至 F 几、速度降到多少、
换哪个焦距档）。

## 3. 系统结构

```
输入        样品图 + 检测需求（测什么 / 精度 / 视野 / 是否运动）
  ↓
诊断        图像质量诊断：灰度差、过曝/欠曝、拉普拉斯方差、强边缘占比
  ↓
计算        相机（分辨率·曝光·帧率）
            镜头（焦距·工作距离·视场角·景深·远心判断）
            光源（方向·颜色·尺寸·偏振）
            控制器（系列·电压功率通道·通讯口）
  ↓
自检        方案代回公式复算 + 冲突检测（景深 / 工作距离 / 曝光 / 靶面 / 通道）
            冲突项反解修复方向（收光圈 F 数 / 速度上限 / 焦距档位反选）
  ↓
输出        一页 HTML 方案书（可打印成 PDF）+ 控制台摘要
```

## 4. 公式与出处

| 计算 | 公式 | 依据 |
|---|---|---|
| 像素精度 | 精度 = 视野 ÷ 分辨率 | 尺寸链基本关系 |
| 需求分辨率 | 视野 ÷ 精度，再按缺陷占 3~4 像素放大 | 按精度反推，再按可检性放大 |
| 曝光上限 | t ≤ 精度 ÷ 运动速度 | 拖影约束 |
| 行频 | 行频 = 运动速度 ÷ 精度 | 线阵采样约束 |
| 焦距 | f / WD = Sensor / FOV（长边配长边；视野长宽比 < 芯片长宽比时取短边） | 相似三角形 |
| 视场角 | 2·atan(Sensor ÷ 2f) | 几何关系 |
| 景深估算 | 2·N·c·(1+β)/β²，c 取 2 倍像元 | 近摄近似 |
| 成像质量判据 | 特征/背景灰度差 ≥ 30、不过曝、不失焦 | 工程经验阈值 |
| 光源方向 | 背光/低角度/高角度/同轴/无影 按任务映射 | 光路与反射规律 |
| 控制器选型 | 光源 → 类型 → 电压/功率/通道 → 通讯口 | 电气匹配 |

景深为近摄近似估算，不是厂商实测值；芯片档位为行业常见规格，采购前须核对实际样本。

## 5. 快速开始

需要 Python 3.10+。图像诊断需要系统 PATH 里有 `ffmpeg`（没有则自动跳过图像诊断）。

```bash
# 划痕检测那道练习题
python run.py --task 表面划痕 --accuracy 0.01 --fov 12x10 --wd 130

# 带样品图（图像诊断 + 光源修正建议）
python run.py --image data/samples/image163.png --task 平面字符 --accuracy 0.05 --fov 40x33 --wd 300

# 曲面亮盖上的字符：声明表面，避免 90° 直射产生镜面强反光
python run.py --image <你的瓶盖图.jpg> --task 平面字符 --surface 曲面 --accuracy 0.05 --fov 30x30

# 飞拍场景：会同时约束曝光时间、帧率、控制器是否要上频闪
python run.py --task 表面划痕 --accuracy 0.02 --fov 30x20 --moving --speed 200 --wd 200

# 大视野 + 高精度（需求超最大面阵档位）：自动按多拍拆分给出量化方案
python run.py --task 表面划痕 --accuracy 0.005 --fov 100x80 --wd 130
# → 25MP 档单幅视野 8.53mm，拆 12×10 = 120 幅；镜头/光源/自检按单幅视野计算

# 完全跳过图像诊断
python run.py --task 尺寸测量 --accuracy 0.01 --fov 8x6 --no-image
```

参数含义见 `python run.py -h`。方案书输出到 `out/spec_<时间戳>.html`，浏览器打开、Ctrl+P 存 PDF。

## 6. 测试

```bash
python -m unittest discover -s tests -v
```

22 个用例，基准全部是可手工复算的算例（不是事后凑的期望值）：

| 用例 | 场景 | 期望 |
|---|---|---|
| 划痕检测选相机 | 小视野、亚丝级精度 | 精度级 1200×1000 → 缺陷级 3600×3000 → 取 1200 万 |
| 焦距计算 | 定焦镜头配大靶面 | f = 67.36mm（手工口算 67mm，差 0.5%） |
| 焦距档位选择 | 工作距离受限 | 75mm 对应 WD 变大，50mm 对应 WD 变小 |
| 控制器选型 | 飞拍与常亮对比 | 一般调光 DPS / 大功率 CPL / 120μs SPS / 30μs BPS |
| 光源方向 | 五类典型任务 | 尺寸测量→背光，划痕→低角度，高反光→同轴+偏振 |
| 曲面高反光修正 | 瓶盖字符只拖图 | 过曝 3.6% + 拉普拉斯方差 14 → 90° 改 30°~45° 低角度 + 偏振 |
| 多拍拆分 | 100×80 @ 0.005mm 超规格 | 单幅 8.53mm → 12×10 = 120 幅，覆盖/精度恒等式 |
| 修复方向反解 | 景深不足 2mm @ β=0.211 | 光圈收至 F5.3（公式逆运算，可手算复核） |
| 阈值自校准 | 合成指标判级 | 校准阈值下临界变合格/合格变临界，两级推导一致 |

合计 62 个用例（含线阵 7 个，见第 12 节）。

**为什么不能一律 90°**：任务名只说"检什么"，不说"工件是什么面"。`平面字符 → 环形光 90°`
是按平整漫反射面外推的；弧面亮盖上直下打会形成镜面强反光、局部过曝。网页的「工件表面」
可显式选曲面/高反光/镜面；只拖图时，若诊断出现过曝 > 3% 且拉普拉斯方差 < 15，
也会自动回写光路（尺寸余量仍为视野×1.2，不受角度修正影响）。见 `tests/test_light_surface.py`。

焦距用例与手工口算的 0.36mm 差异来自靶面取值（5.7 还是 5.4mm），属于可解释偏差，已在用例注释中说明。

## 7. 图像诊断指标的选取过程

最初用"相邻像素差分均值"衡量清晰度，实测发现三张清晰度差异明显的图都得到 2~3 的低分——
因为大片均匀背景把均值稀释了。改用拉普拉斯方差后，在自建对照组上得到：

| 图 | 拉普拉斯方差 | 判定 |
|---|---|---|
| 原始样张 | 290 | 清晰 |
| 高斯模糊 σ=1.5 | 61 | 可接受 |
| 高斯模糊 σ=3 | 14 | 模糊，报不通过 |

阈值由此确定，不是拍脑袋定的。

**输入格式**：图纸支持 PDF / TXT（有文字层），样张支持 JPG / PNG / BMP / WEBP / TIFF。
两类文件走不同路径——

| 输入 | 能推出 | 推不出 |
|---|---|---|
| 图纸 PDF/TXT | 视野、精度、检测任务 | 现场成像质量 |
| 样张 JPG/PNG | 灰度差、过曝、清晰度、判定 | **视野与精度**（图里没有标定尺） |

所以样张只喂给成像诊断，不会改写四项计算。没放样张时页面会明说“本次跳过成像诊断”，
而不是悄悄按默认值算出一份看着像真的方案。

仓库内附带一张 ffmpeg 合成的样张 `data/samples/sample_part.png`（3.5KB，无第三方版权），
点“用内置合成样张”即可试；真实样张请自行提供。

这些阈值现在也支持**用你自己的产线样本校准**——好坏各 3 张以上样张，
程序取两组均值的中间点作为本产线判级阈值：

```bash
python run.py --calibrate good_samples/ bad_samples/   # 写入 out/thresholds.json
python run.py --image 样张.png --task 表面划痕 ...       # 自动加载校准阈值
```

校准只覆盖提示级阈值（灰度差 / 过曝占比 / 拉普拉斯方差）；严重级由提示级按固定比例
推导（2/3、10/3、8/15），推导比例让内置默认值与原版手写阈值完全一致。方案书里会
注明本次判级阈值的来源（内置经验值 / 校准组张数）。

## 8. 图纸驱动：从产品图反推检测条件

真实工作流里工程师拿到的不是"四行参数"，是一张图纸。图纸上有外形尺寸、公差、外观要求，
检测条件本来就是这些数字推出来的。

```bash
# 先用任意工具把 PDF 转成文本，再喂给程序
python run.py --drawing-txt data/samples/sample_drawing.txt --wd 150
```

网页版支持直接拖入 PDF（内部调用本机的 PDF 转文本工具）。

**仓库内样例**（`data/samples/sample_drawing.txt`，合成图纸，不含任何厂商内容）：

```
图纸反推　置信度 高
  · 外形最大尺寸 12.8 mm，次大 7.4 mm，视野留 20% 余量 → 15.36×8.88 mm
  · 最严公差 ±0.05（公差带 0.1 mm）→ 按 1:5 折算，测量分辨力需求 0.0200 mm
  · 最小可检特征取毛刺 0.02 mm（占 3 像素 → 像素精度 0.0067 mm/px）
  · 该像素精度同时满足测量分辨力需求
  → 相机 5MP 2448×2048，像素精度 0.0063 mm/px，环形光 30° 暗场，APS 控制器
```

这份样例是**为演示合成**的，结构与真实工程图一致（单位、一般公差表、尺寸标注、毛刺要求），
但不含任何厂商图纸内容。真实图纸请自行提供，程序不预设任何特定产品。

> 开发期曾用一份厂商连接器图纸（14.94×11.7 mm、公差带 0.05）验证过：
> 本工具算出像素精度 0.0093 mm/px，与一个已落地项目实测的 0.0088 mm/px 相差 6%，
> 差异来自对方视场更大（21.59×18.07）。该图纸属第三方资料，不随仓库分发。

解析用到的工程惯例：

| 判据 | 取值 | 说明 |
|---|---|---|
| 测量不确定度 | 公差带 ÷ 5 | 要判定 ±T 的公差，量具误差应小于公差带的 1/5 |
| 缺陷可检性 | 缺陷尺寸 ÷ 3 | 一个缺陷至少落在 3 个像素上才检得稳 |
| 视野余量 | 外形 × 1.2 | 工件不会永远摆在正中间 |

识别范围：对称公差 `±0.05`、不对称公差 `+0.03/-0.02`（含 PDF 折行）、一般公差表
`2 PLACES ± 0.05`、最大允许毛刺 `NOT EXCEED 0.02 MM`。角度公差（带 °）自动排除。

## 9. 与 Yvison 的对接

Yvison 的相机参数模板在 `Config/Parameter/User_Camera.xml`（内容是 JSON）。
实测该文件已包含本方案输出的全部关键字段，因此可以直接生成参数模板：

```bash
python run.py --task 表面划痕 --accuracy 0.02 --fov 30x20 --moving --speed 200 --wd 200 \
  --yvison-camera "F:/Yvisionn/Yvison/Config/Parameter/User_Camera.xml"
```

会额外输出 `out/User_Camera_海康_方案值.xml`，并逐项打印 旧值 → 新值：

| 字段 | 来源 | 示例改动 |
|---|---|---|
| Width / Height | 相机档位 | 720×540 → 5472×3648 |
| ExposureTime | 曝光上限 t ≤ 精度÷速度 | 200 → 100（μs） |
| Gain | 增益会同时放大噪声，建议置 0 | (空) → 0 |
| TriggerMode / TriggerSource | 飞拍→外触发，静止→软触发 | Off→On / Software→Line0 |
| PixelFormat | 黑白 → Mono8；彩色不动 | YUV422 → Mono8 |

**只生成副本，不覆盖原文件。** 核对后自行替换并重启软件。

不能直接写进去的部分：光源（`led` 模块只暴露 name/brand/port，通道与亮度需软件运行时
用 `get_hardware_config led` 确认）、镜头与控制器型号（属于采购信息，不在软件配置里）。

## 10. 前端结构

界面拆成三个页面，共用一套设计令牌（`ui/src/index.css` 的 `@theme`），不再各页各写一套样式。

| 路由 | 页面 | 职责 |
|---|---|---|
| `/` | 首页 | 一句话主张、四步流程、两个入口 |
| `/studio` | 方案工作台 | 图纸或样张输入，四组结论、成像诊断、自检、流程、导出 |
| `/about` | 边界与方法 | 计算依据表、做不到什么、四次改动 |
| `/exploded` | 3D 拆解 | 独立静态页（Three.js），左上角「← 返回」回工作台 |

**技术栈**：Vite + React 18 + Tailwind CSS v4 + React Router + lucide-react + framer-motion。
依赖只装实际用到的六个，没有 shadcn CLI（组件量小，直接写更省），也没有引入状态库/请求库——
工作台是单页单次请求，`useState` 足够；再加一层缓存等于给三个请求套框架。

**构建与部署**：

```bash
# 方式一：双击根目录「构建前端.cmd」（首次会自动装依赖）
# 方式二：命令行
cd ui && npm install && npm run build     # 产物 ui/dist
python demo_server.py 8848                # 服务直接托管 dist
```

仓库里**没有**：`ui/node_modules`（约 200MB）、`ui/dist`（构建产物，需自行生成）、
第三方图纸与课件截图（版权不属于本项目）。克隆后请先构建一次，否则服务会退回旧版单页。

`demo_server` 会优先读 `ui/dist/index.html`，产物不存在时退回旧的 `web/index.html`，
所以没装 Node 的机器也能把演示跑起来——只是看到的是旧版单页。

**改样式改哪里**：颜色、字号、圆角、间距全部在 `ui/src/index.css` 的 `@theme` 里；
组件在 `ui/src/components/ui.jsx`（按钮只有 primary/outline/ghost 三种，面板只有一种容器形态）；
页面在 `ui/src/pages/`。改完 `npm run build` 即可，不用重启 Python 服务。

## 11. 3D 拆解视图（`/exploded`）

三维页面不是画死的模型，**每一层都由 `/api/scene` 返回的选型结果生成**。

上层参数一改，机身形态就换：

| 变化 | 三维上看得到 |
|---|---|
| 面阵 → 线阵 | 方形机身变成细长条形，镜头换成长筒 M42，光源由环光变线光 |
| 分辨率档位 | 机身随像素数略微变大 |
| 定焦 → 远心 | 短镜筒变成粗长镜筒，前组带台阶 |
| RS 环光 → HFS 背光 | 圆环 + 灯珠阵变成整块发光平板 |
| → CO 同轴 | 立方体分光模块，45° 半透片 + 侧向进光口 |
| → DS 圆顶 | 半球腔体罩住工件 |
| → 2BS 条形 | 两侧对射长条 |
| 控制器通道数 | 指示灯数量跟着变（2/4/8 路） |

页面顶部有 5 个预设，对应 5 台不同的机器：

```
划痕 · 环光 · 面阵      15×12 / 0.03mm        → RS 环光 + 定焦 + 2MP 方机身
尺寸 · 背光 · 高像素    12×10 / 0.01mm        → HFS 背光 + 远心 + 12MP
高反光 · 同轴          40×33 / 0.05mm        → CO 同轴模块
曲面 · 圆顶            60×50 / 0.1mm         → DS 半球腔
飞拍 · 线阵 8K         80×60 / 0.05 / 300mm/s → 8K 线阵长条 + LPG 线光
```

**输入源不止预设**：

- 左侧面板可直接**拖入产品图纸**（PDF / TXT），解析出的视野、精度、任务会立刻重建三维机台
- 没有图纸时点「用示例连接器图纸 →」，走的是同一套解析（`/api/drawing-sample`）
- 从主界面跳转时，链接会带上当前表单参数（`/exploded?task=…&accuracy=…&fov=…&wd=…`）
- 图纸给不出工作距离，按 160 mm 装配，页面上会写明这一点
- 四平台节点对照不再写死：`/api/scene` 返回当前任务的 `flow`，换任务/图纸后节点数与节点名同步重建

举例：默认是「尺寸测量 / 12×10 / 0.01」，机上是一块白色平板背光 + 远心长筒 + 4096×3000；
拖入 Molex 连接器图纸后，变成**环形灯珠 + 定焦短筒 + 1600×1200**——因为图纸要求的是
毛刺 0.03mm 的外观检测，不是尺寸测量。光路、镜头、相机同时换掉。

交互与显示：

- 点部件 → 该层向外拆出、出现选择环，右侧给参数表 **和 10 步计算过程**
- 点卡片 → 视图中央展开该平台的 7 个功能节点链（大恒 / 海康 VM / 凌云 / HALCON）
- 拖动旋转、滚轮缩放、双击复位、空格全部拆解
- 深链：`?preset=line`、`#vm`、`#cam`、`#explode`

技术上是零外部依赖的：`web/vendor/three.min.js` 取自本机已有的打包版本（含 `RoundedBoxGeometry`、
`EffectComposer`、`UnrealBloomPass`），通过 `/vendor/` 路由静态提供，不走 CDN。

节点命名与导出物的对应关系仅作**命名对照**，不声称可在平台之间直接互转工程文件。

### 光学实验室（`/lab`）

3D 拆解页回答的是「这台机长什么样」，实验室回答的是「这套光到底打在工件哪里」。
工作台生成方案后点「进光学实验室调试」，会带着推荐的光源系列与视野进来。

光源模型按工业实际建模，**灯体保持水平安装，改的是灯珠内倾角**：

| 形态 | 发光角 α 的物理含义 | 光斑半径 |
|---|---|---|
| 环形光 / 条形光 / 线光源 | 灯珠相对水平面的夹角，α=90° 垂直向下，α 越小越掠射 | `\| r − h·cot α \|` |
| 面光源 / 平行面光源 | 整块面板绕自身轴倾斜，光沿面板法线 | 面板投影 |
| 圆顶光 / 隧道光 | 内壁漫射，方向指向工件中心 | 罩体开口范围 |
| 同轴光 | 沿光轴垂直向下，45° 半反镜折转 | 镜头视场 |

所以拖低发光角会看到光斑**真的缩成一点再散开**（`r = h·cot α` 时汇聚），拖高则扩散到工件外、
HUD 直接标「打飞」——这是公式推演的结果，不是动画。光源尺寸随视野等比缩放，覆盖判定按工件台面。

三种拖拽（3D 里直接对灯具操作）：

- 直接拖 → 水平面内平移，改 X / Z 偏移
- **Shift** + 拖 → 改安装高度
- **Alt** + 拖 → 改发光角
- 双击灯具复位；双击空白处复位视角

左侧另有五个滑块给出精确数值。换光源时不带 WD：相机工作距离和光源安装高度是两件事，
混用会默认把灯具架到光直接打飞的位置。

和参考的 OPT-RIA 光路模拟器相比，这里借的是交互形态（左控制 / 中 3D / 实时反馈），
但光源库来自项目自己的 7 种形态，且**不做定量照度仿真**——页面底部这句边界说明不能删。

## 12. 线阵支持

面阵与线阵是两条不同的推算路径，不能混：

| | 面阵 | 线阵 |
|---|---|---|
| 分辨率来源 | 视野宽 × 高 ÷ 精度 | 只有横向：扫描宽度 ÷ 精度 |
| 另一维 | 由传感器给定 | 由**行频**生成：行频 = 速度 ÷ 像素精度 |
| 纵向变形 | 无 | 行频不对，圆会拉成椭圆 |
| 曝光约束 | t ≤ 精度 ÷ 速度 | 单行曝光 ≤ 1 ÷ 行频 |
| 带宽 | 像素数 × 帧率 | 像素数 × 行频（8K@30kHz ≈ 250 MB/s） |
| 镜头 | C 口，像面小 | M42 / F 口，像面宽 |

`select_camera(..., scan="line")` 走线阵分支，`tests/test_line_scan.py` 用 7 个用例守住三条恒等式：
像素精度 × 像素数 = 视野宽、行频 × 像素精度 = 速度、数据率 = 像素数 × 行频。

## 13. 已知边界

- 不控制物理光源。有可编程控制器（CST DPS 的 B/C 版带串口/网口）时才谈得上闭环，本项目未实现。
- 图像诊断基于灰度，颜色判据（白平衡、色差）只给出方向性建议，未做量化。
- 芯片档位表是行业常见规格，不是任何一家厂商的选型手册。
- 景深为估算值，依赖光圈 F 数和容许弥散圆假设。
- 不处理线阵相机的行频与运动匹配细节，仅给出面阵场景的帧率下限。
